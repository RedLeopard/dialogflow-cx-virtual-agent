## Screened transfer setup

Function source: [`../twilio/functions/maya-transfer.js`](../twilio/functions/maya-transfer.js). Deploy it in the existing Twilio Functions service with path `/maya-transfer` and **Protected** visibility.

| Environment variable | Value |
| --- | --- |
| `MAYA_OWNER_CELL` | The real owner cell number in E.164 format. Do not copy a sample destination. |
| `MAYA_STUDIO_WEBHOOK_URL` | This flow’s Webhook URL from Studio **Details**, beginning `https://webhooks.twilio.com/v1/Accounts/`. Use the Webhook URL, not the REST Executions URL. |

The deployed source uses the business number as `callerId`; `MAYA_BUSINESS_NUMBER` is not required by this version. Save code and Deploy All after changing the function. Environment-variable edits take effect without a code deployment once committed in the console.

Wire Studio as follows:

1. Keep Trigger Voice connected to `connect_virtual_agent_1`.
2. Connect its **Live Agent Handoff** to a **TwiML Redirect** named `screened_transfer`.
3. Set its URL to the deployed `/maya-transfer` function, method POST, and retain the default 14400-second redirect timeout shown in the screenshot. This is different from the function’s 15-second dialing timeout.
4. Connect `screened_transfer` **Return** to `missed_call_message`, then save and publish Studio.
5. Keep the message widget’s custom `VOICEMAIL` welcome event, `mode=voicemail`, voice override, and caller-context mappings. Verify those mappings during a real message test.

The function dials the owner with screening on the called leg. After answering, the owner hears “[Firm name]. Press 1 to accept this call.” A 1 permits bridging; an empty or other response ends only the owner leg. An unbridged result redirects the original caller to Studio with `FlowEvent=return`. A bridged conversation ends normally when the transfer finishes.
